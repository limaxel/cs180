# CS180 Project 3: Flow Models

<p>Part A uses a pretrained flow model for denoising, editing, and visual illusions.
      Part B trains UNets on MNIST.</p>

<!--more-->

# Setup

<p>For Part A I used the provided PixNerd adapter at \(512\times512\), with float32 states,
      Euler step size 0.02, and guidance weight 7 where CFG is used. For Part B I used
      MNIST and the assignment's UNet architecture. The main random seed was 180; the logo
      comparisons used 210, 211, and 212.</p>

<a id="part-a"></a>

# Part A: Exploring flow models

<p class="chapter-deck">At time zero the state is Gaussian noise; at time one it is a clean image. The model estimates the velocity between them.</p>

<p><strong>Flow equation:</strong> \(x_t=(1-t)\varepsilon+tx_1\)</p>

<a id="a-forward"></a>

## Constructing noisy training inputs

<p>I used my squirrel photo, center-cropped it to \(512\times512\), and mapped RGB to \([-1,1]\). The forward process is \(x_t = (1-t)\varepsilon + tx_1\). I saved the image and one Gaussian noise tensor, then reused that exact pair at <em>t</em> = 0.25, 0.50, and 0.75 throughout the denoising comparisons. Higher <em>t</em> means less noise and more of the original image.</p>

<a id="a-denoise"></a>

## Gaussian blur and one-step denoising

<p>Blur was the first thing I tried. I applied it to \(\frac{x_t}{t}\) so the clean-image contribution had the right amplitude. I tried \(\sigma=1,2,4,8,16\), and picked the lowest-MSE result for each time using the known original. It removes some noise, but the squirrel and wall get very blurry.</p>

<p>My next attempt uses one model prediction: \(\hat{x}_1 = x_t + (1-t)v_{\theta}(x_t,t,c)\), with <code>c = "a high quality photo"</code>. This predicts velocity, not noise. It does a much better job with the outline, though the small details are still smoothed out.</p>

<a id="a-velocity"></a>

## Predicted updates and error

<p>The model update is \(\hat{\Delta} = (1-t)v_{\theta}(x_t,t,c)\). Since I saved the clean image and noise, the target is \(\Delta^{*} = (1-t)(x_1-\varepsilon)\). I compute \(\sqrt{\operatorname{mean}_{\mathrm{RGB}}\!\left((\hat{\Delta}-\Delta^{*})^2\right)}\) at each pixel before any clipping or display scaling.</p>

<p>All predicted and target updates use one symmetric RGB scale, with zero at middle gray. All three error maps use the same linear color limits. The larger errors follow the fur, wall texture, and window edges. The flat areas are darker.</p>

<a id="a-euler"></a>

## Iterative denoising

<p>One prediction treats the rest of the path as a straight line. I changed that to small Euler updates: \(x_{t+h} = x_t + h\,v_{\theta}(x_t,t,c)\). The velocity is recomputed each time. Starting from the saved \(t=.50\) input, \(h=.02\) gives 25 updates. The sampler shortens the last step when needed so it ends at exactly t=1.</p>

<p>I also checked the sampler against a constant velocity field, including a start at .93 where the last step is only .01. Below are the initial state, every fifth update, and the endpoint.</p>

<a id="a-generation"></a>

## Sampling with and without CFG

<p>I started from five independent Gaussian tensors, seeds 180-184, and took 50 Euler steps with a high quality photo. All five results are people, even though the prompt never asks for a person. Some faces and bodies are badly formed.</p>

<p>I then reused the same five initial noises with CFG: \(v = v_c + 7(v_c-v_u)\). Both branches see the same x and t, and the unconditional prompt is the empty string. With w=0 this reduces to the original conditional prediction. Guidance fixes a lot of the facial structure and sharpens the images, but all five are still portraits, so guidance does not fix the narrow subject range.</p>

<a id="a-editing"></a>

## Image-to-image editing

<p>For each source I made \(x_t = (1-t)\varepsilon + tx_1\) and sampled from that time to 1. I used the generic photo prompt, CFG \(w=7\), \(h=.02\), and seed 180. Every sweep includes the original plus \(t\in\{.02,.04,.06,.10,.14,.25,.50\}\). Lower t gives the model less of the source to work with; higher t keeps more of its layout.</p>

<a id="a-illusions"></a>

## Visual anagrams and hybrid images

<p>For anagrams, let F rotate an image by \(180^\circ\). At every step I use \(\frac{1}{2}\left[v_{\mathrm{cfg}}(x,t,c_1)+F^{-1}\!\left(v_{\mathrm{cfg}}(F(x),t,c_2)\right)\right]\). Flipping the second velocity back before averaging matters as both updates need to be in the same orientation. These use seeds 180 and 181.</p>

<p>The old-man/campfire pair is the stronger one for me. The horse is readable in the second pair, but the upright view is closer to a loose mountain sketch than a clear snowy village. The prompts are shown on each view.</p>

<p>For the hybrids I used \(\operatorname{LP}(v_a)+v_b-\operatorname{LP}(v_b)\) inside each Euler update. LP is a Gaussian blur with kernel size 265 and \(\sigma=16\) at \(512\times512\). The full prompts are "a lithograph of a skull" / "a lithograph of a waterfall", and "a lithograph of a cat" / "a lithograph of a forest". The small views help with the broad face shapes, while the full-size images show the waterfall and trees. The skull/waterfall works better for me. The forest has face-like shading, but it is a weaker, less clearly cat-like result.</p>

<a id="a-bells"></a>

## Bells & Whistles: Extra transformations and course logo

<p>I tried two extra views: a \(90^\circ\) rotation and colour inversion. For the quarter-turn, the inverse is a \(270^\circ\) rotation; for colour inversion in \([-1,1]\), the transform is \(x\mapsto -x\) and is its own inverse. I used the same transformed-velocity averaging as above, with seeds 200 and 201. These are simple orthogonal transforms, so Gaussian starting noise keeps the same distribution.</p>

# Part B: Flow matching from scratch

<p class="chapter-deck">First a single-step denoiser, then a time-conditioned flow model, then labels for more control.</p>

<p><strong>Flow equation:</strong> \(v^{*}=x_1-x_0\)</p>

<a id="b-denoising"></a>

## Training the denoiser

<p>I implemented the Conv, DownConv, UpConv, Flatten, Unflatten, and composed blocks, then joined them into the assignment's UNet. Conv uses \(3\times3\) convolution, batch normalisation, and GELU. DownConv halves the resolution, UpConv doubles it. Two downsampling stages go from \(28\times28\) to \(14\times14\) to \(7\times7\), followed by a \(1\times1\) bottleneck and skip concatenations on the way back up.</p>

<p>The first model predicts a clean image from \(z = x + 0.5\varepsilon\), using pixel MSE. I used D=128, batch size 256, Adam at \(10^{-4}\), and five epochs. Only the 60,000 training digits are used for optimisation, the 10,000 test digits are for evaluation. The loader is shuffled and fresh noise is drawn every batch, rather than making one fixed noisy dataset.</p>

<p>The plots show raw minibatch loss and a 100-step moving average. Whenever I quote a Part B training loss below, it is the mean of the last 100 minibatches, not test-set error. For this denoiser that value is <strong>0.008415</strong>.</p>

## Different noise levels and pure noise

<p>The denoiser only trained at \(\sigma=.5\). I kept one test digit and one Gaussian draw fixed, then tried \(\sigma\in\{0,.2,.4,.5,.6,.8,1.0\}\). It still reads as a 7 across the sweep, but the output gets messier at the high-noise end.</p>

<figure class="figure wide tall-study"><a class="p3-image-popup" href="/cs180/assets/images/proj3/partb/denoiser_ood.png"><img alt="Out-of-distribution denoising: rows increase sigma from 0 to 1, left is noisy input and right is prediction" src="/cs180/assets/images/proj3/partb/denoiser_ood.png"/></a><figcaption><span>OOD sweep</span> Top to bottom: \(\sigma=0\), .2, .4, .5, .6, .8, 1.0. Left: input, right: prediction.</figcaption></figure>

<p>Next I trained a fresh D=128 model for five epochs with the same Adam and batch settings, but fed it pure noise independent of each clean target. This failed to produce varied digits where the samples were almost the same blurry shape. Under MSE, the best prediction is \(\mathbb{E}[x\mid\varepsilon]\). Since \(\varepsilon\) and \(x\) are independent here, that becomes \(\mathbb{E}[x]\), the pixelwise average over the training digits.</p>

<a id="b-time"></a>

## Time-conditioned flow matching

<p>For the next model I predict velocity along a noise-to-digit path instead of asking for a complete digit in one jump. Each batch gets fresh Gaussian noise \(x_0\), clean digits \(x_1\), and a time (\t\) sampled independently and uniformly from [0,1] for each example. The input is \(x_t = (1-t)x_0 + tx_1\) and the MSE target is \(x_1-x_0\).</p>

<p>Two FCBlocks embed the normalised time and multiply the unflattened bottleneck and first upsampled features. I used D=64 (1,996,417 parameters), batch size 64, ten epochs, and Adam starting at .01. After every epoch the learning rate is multiplied by \(0.1^{1/10}\).</p>

<p>Sampling starts at Gaussian noise and takes 50 Euler steps of size 1/50. I kept the sampling seed at 200 for epochs 1, 5, and 10, so changes below are not from picking different noise. This is much more varied than the pure-noise regressor. Some strokes still join up badly or look like more than one digit.</p>

<a id="b-class"></a>

## Class-conditioned flow matching

<p>I added two more FCBlocks for a one-hot digit label. At the bottleneck and first upsampling stage the class embedding scales the features and the time embedding is added. During training, 10% of examples get an all-zero class vector so the same model also learns the unconditional branch.</p>

<p>This uses D=64, batch size 64, ten epochs, Adam starting at .01, and the same per-epoch exponential decay as the time-only baseline. Training times are sampled independently and uniformly from [0,1]. Sampling takes 300 Euler steps with \(v = v_u + 5(v_c-v_u)\).</p>

<p>Every grid has four rows of labels 0-9: four instances of each digit. I reused sampling seed 210 at all three epochs. Label control is clear by epoch 10, although some strokes are still uneven</p>

## Bells & Whistles: Larger time-only model

<p>The D=64 time-only samples still had some broken or muddled strokes. I tried D=128 and 20 epochs instead of ten. That raises the parameter count from 1,996,417 to 7,974,145. Batch size stays 64 and Adam starts at .01, the decay is now \(0.1^{1/20}\) per epoch so the total decay is still one decade.</p>

<a id="takeaways"></a>

# Notes after the experiments

**More steps did not mean lower MSE.** Euler made a more textured squirrel, but one-step was closer in pixels. I need to look at the image and the metric rather than treating either one as the whole answer.

**Keeping the source can also keep the problem.** Large starting times kept my drawings recognisable, but also kept them looking like drawings. Lower times sometimes turned them into unrelated flat objects.

**The logo needed a different input.** A fancier prompt improved the camera texture. Changing the source to the Campanile-eye collage made the design less generic. The small times still produced fake text.

**A one-step noise regressor mostly learned the average.** Flow matching avoided that mean-like output by learning a time-dependent velocity field. Class labels added much more control over which digit appeared.
